# DisplayList Explorer Logo Design Board

## Brand Read

- **Logo type:** product/app identity for an open-source developer tool.
- **Audience:** SwiftUI and OpenSwiftUI implementers, framework engineers, reverse engineers, and developers investigating rendering behavior.
- **Core promise:** reveal the correspondence between a verbose SwiftUI `DisplayList.description` and its compact `minimalDescription` encoding.
- **Personality tension:** precise but approachable; low-level but visual; analytical but fast; native to developer tools without looking like another generic code utility.
- **Primary uses:** 16 px browser favicon, 32 px website header, README hero, GitHub social preview, and repository avatar.
- **Assumptions:** retain the product's ink/orange visual relationship; treat blue as an interface state rather than a required logo color; use the full `DisplayList Explorer` wordmark outside the favicon.
- **Avoid:** Swift bird or Apple references, magnifying glasses, mouse cursors, generic angle brackets, browser windows, node trees, glossy gradients, 3D card stacks, and decorative detail that disappears below 32 px.

## Designer Board

The following are public-method lenses, not attempts to imitate a designer's visual style.

### Paul Rand lens

- **Core bias:** one memorable idea in one simple form.
- **Question:** does the symbol communicate transformation or correspondence without a caption?
- **Positive pressure:** removes decorative “developer tool” clichés.
- **Red flag:** a clever code pun that needs explanation.

### Massimo Vignelli lens

- **Core bias:** disciplined geometry that behaves consistently across an identity system.
- **Question:** does the mark work as a one-color shape on a grid at 16 px?
- **Positive pressure:** forces repeatable radii, spacing, and durable proportions.
- **Red flag:** fashionable rendering effects substituting for form.

### Paula Scher lens

- **Core bias:** identity should have voice and presence beyond the small icon.
- **Question:** can the symbol drive a website header and GitHub cover without becoming background decoration?
- **Positive pressure:** connects the mark to a confident wordmark and editorial system.
- **Red flag:** reduction so neutral that the tool becomes anonymous.

### Michael Bierut lens

- **Core bias:** the identity must solve the real usage ecology.
- **Question:** does the mark help users recognize the browser tool, repository, documentation, and shared links as one product?
- **Positive pressure:** prioritizes favicon, header lockup, README, and social preview over merchandise mockups.
- **Red flag:** a polished presentation board hiding an impractical symbol.

## Strategy

- **Logo job:** signal “one rendering structure, two linked representations” and make an obscure framework artifact feel inspectable.
- **Category code to borrow:** ordered structure, traceability, compact tokens, and restrained developer typography.
- **Category code to break:** literal code brackets, cursors, magnifiers, terminal windows, and blue-purple SaaS gradients.
- **Designable tension:** detailed source ↔ compact encoding; structure ↔ reduction; systems precision ↔ immediate legibility.
- **Recommended mark type:** an abstract symbol or geometric monogram with strong negative space, paired with a restrained neo-grotesk wordmark.
- **Palette:** ink navy `#172033`, warm ivory `#F7F4EE`, and one restrained orange `#EF5B2A` accent. The mark must also work as a single black shape.

## Concept Territories

### 1. Compact Trace

- **Thesis:** many nested rendering traces resolve into one compact token.
- **Mark type:** abstract structural symbol.
- **Construction:** three bold stepped traces share a common terminal edge and progressively reduce toward one square aperture. No arrows or perspective.
- **Typography:** compact neo-grotesk wordmark; `DisplayList` semibold, `Explorer` regular.
- **One-color behavior:** all traces and the terminal aperture merge into a single memorable silhouette.
- **Supported by:** Rand's single transformation idea; Vignelli's repeatable geometry; Bierut's direct connection to the product workflow.
- **Challenged by:** Scher asks for enough attitude to avoid resembling a generic analytics mark.
- **Vector notes:** construct on a 12 × 12 grid using three equal-width paths, one radius, and a square counter; optically widen the lowest trace.
- **Risk:** could be misread as descending bars or a funnel; test without explanation.

### 2. DL Fold

- **Thesis:** the product name and its function collapse into one ownable mnemonic.
- **Mark type:** geometric `D`/`L` monogram, not ordinary typeset letters.
- **Construction:** one continuous outer `D` frame folds inward to create an `L`-shaped list path; a square counter represents the compact token.
- **Typography:** neutral wordmark so the custom monogram carries the voice.
- **One-color behavior:** one uninterrupted silhouette with one negative-space counter.
- **Supported by:** Rand's mnemonic simplicity; Vignelli's modular letter geometry; Scher's demand for recognizable brand voice.
- **Challenged by:** Bierut flags collision risk with existing `DL` monograms.
- **Vector notes:** begin with a squared `D`, remove the conventional stem, and let the inner terminal define the `L`; use one radius family and no stroke outlines.
- **Risk:** may look like a generic logistics or design-studio monogram; requires a collision and misread test.

### 3. Shared Range

- **Thesis:** the same highlighted range exists in both the source and compact representation.
- **Mark type:** abstract linked-range symbol.
- **Construction:** two solid structural halves share one aligned negative-space slice; a single orange block occupies the correspondence point without using arrows or panes.
- **Typography:** technical neo-grotesk with a subtle monospace secondary label system.
- **One-color behavior:** the shared slice stays visible as negative space after the accent color is removed.
- **Supported by:** Bierut's usage specificity and Vignelli's grid discipline.
- **Challenged by:** Rand questions whether the mapping idea is memorable enough; Scher asks for a stronger silhouette.
- **Vector notes:** use mirrored block geometry but intentionally offset the shared range by half a module to avoid a generic `H`.
- **Risk:** could resemble compare, sync, or link icons already common in developer tooling.

### 4. Frame Token

- **Thesis:** rendering frame outside, minimal encoded token inside.
- **Mark type:** nested container symbol.
- **Construction:** a rounded frame with one compact inset square and a single cut connecting them.
- **Risk:** too close to generic app, window, or scan icons. Reject unless a uniquely ownable negative-space solution appears.

## Board Critique

| Public-method lens | Compact Trace | DL Fold | Shared Range | Frame Token |
|---|---|---|---|---|
| Rand | Clear transformation; simplify to one silhouette | Strong mnemonic; avoid a forced letter trick | Correct idea but may feel diagrammatic | Too generic to remember |
| Vignelli | Strong grid and one-color potential | Excellent construction discipline | Works if the shared slice survives monochrome | Clean but category-indistinct |
| Scher | Needs a confident lockup to add voice | Best brand presence of the four | Useful system motif, weaker hero mark | Anonymous at cover scale |
| Bierut | Directly explains source → compact | Practical across favicon and repository if collision-safe | Most faithful to linked-hover behavior | Familiar but says little about the product |

## Recommendation

Render **DL Fold** and **Compact Trace** as the primary finalists, with **Shared Range** as a function-first challenger. Reject Frame Token. Evaluate each in a restrained identity board containing the hero symbol, horizontal wordmark, one-color reversal, and 16/24/32 px samples. Raster output is concept art; the selected mark still requires deterministic vector redrawing, optical correction, and a trademark/collision search before production use.
